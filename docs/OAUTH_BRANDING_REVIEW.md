# Google OAuth 브랜딩 요구사항 검토

검토일: 2026-10-26 (한국 시간). 대상: `paylog-c5c2d`.

기준: [Google 브랜드 인증 공식 문서](https://developers.google.com/identity/protocols/oauth2/production-readiness/brand-verification?hl=ko). 문서를 직접 조회하고 실제 운영 HTML을 HTTPS로 가져와 대조했다. Cloud Console 내부에는 로그인하지 않았으며 계정·권한·브랜딩 값은 사용자가 제공한 화면을 근거로 한다. 아래 결과는 Google의 승인 판정이 아니다.

## 이전 안내 정정

- 개인적으로 아는 소수 사용자만 쓰는 앱은 공식 문서의 개인 용도 검증 예외에 해당할 수 있다. 설문은 실제 사용 목적대로 답한다. 승인받기 위해 개인용 여부를 거짓으로 바꾸지 않는다.
- HTML 파일, 메타태그, GA, GTM, DNS를 모두 인증할 필요는 없다. 이미 확인된 소유자라면 추가 방법 설치가 OAuth의 소유권 오류를 해결한다는 근거는 없다.
- Google 관리 Firebase 기본 도메인의 DNS TXT 레코드는 프로젝트 소유자가 수정할 수 없다. DNS 인증을 위해 새 개인 도메인을 구매해야 한다는 뜻도 아니다.
- 공식 문서는 심사팀이 추가 정보를 이메일로 요청할 수 있다고 안내한다. 이메일 수신은 항상 발생하는 필수 단계가 아니므로, 메일이 없다는 이유만으로 제출 실패를 단정하지 않는다.
- 자동 검토는 보통 수 분, 수동 검토는 통상 영업일 2~3일로 안내하지만 이는 보장 시간이 아니다. 소유권 전파의 24시간과 심사 처리 기간은 별개다.
- 브랜딩 세부정보 변경은 초안에 저장된다. 검토 성공 결과는 7일 유효하며 그 안에 브랜딩을 게시하지 않으면 재확인이 필요하다고 문서가 안내한다.

## 다음 확인 순서

1. 홈페이지의 영구 기능 설명·개인정보처리방침 링크를 보완한다. 현재 검토는 제품 코드를 변경하지 않았다.
2. OAuth 클라이언트 목록과 승인된 JavaScript 원본·리디렉션 URI, 데이터 액세스 범위를 확인해 숨은 도메인이나 누락 선언이 없는지 대조한다. 클라이언트 비밀키·토큰은 수집하지 않는다.
3. 초안과 게시된 브랜딩 중 실제 확인 대상이 무엇인지 확인하고, 소유권 오류에서 추가 검토를 선택한 뒤 최종 제출 결과를 확인한다. 검토 중이면 불필요하게 취소·재시작하지 않는다.
4. Google이 실제로 보완 메일을 보냈다면 그 대화에 증빙을 회신한다. 자동 확인이 계속 실패하면 '도메인 소유권 확인 화면과 IAM은 정상인데 어떤 URL/계정 조건이 실패했는지' 수동 검토에서 구체적으로 확인받는다.

## 검증 한계

Python HTTPS로 공식 문서·운영 HTML을 확인했다. Chromium에서 운영 URL은 이 실행 환경의 인증서 신뢰 설정 때문에 열리지 않아 검사를 중단했고 인증서 검증을 끄지 않았다. 대신 내려받은 운영 HTML을 로컬 Chromium에 로드해 first-frame 이벤트 전후의 링크가 2개에서 0개가 되는 것을 확인했으며, Flutter 화면 소스에서 초기 달력에는 정책 링크가 없고 설정에만 있는 것을 대조했다. 이 실험은 실제 운영 Flutter 전체 렌더링 검사를 대신하지 않는다.

## Firebase Auth 전환 브랜치 후속 변경

`feat/firebase-auth-migration`에서는 로그인 연결과 함께 초기 HTML에 기능 설명을 추가하고, Flutter 달력 첫 화면에도 기능 설명·정책 링크를 유지하도록 보완했다. 이는 아직 운영 URL에서 확인한 결과가 아니며 브랜치 배포 후 별도 확인이 필요하다. 사용자가 추가로 제공한 OAuth 클라이언트 화면에서 두 JS 원본과 비어 있는 리디렉션 URI를 확인했고, 이 앱의 팝업 토큰 방식에 맞는다. 데이터 액세스 화면에서 OpenID·이메일·프로필·Sheets 범위의 선택도 확인했다. 새 Firebase 로그인은 Sheets 범위를 요청하지 않으며 최종적으로 Sheets 저장 경로를 대체할 예정이다.
