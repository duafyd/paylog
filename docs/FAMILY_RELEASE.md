# 현재 배포 기준 (2026-10-28)

공유 Google Sheets + GAS, Android 1.3.0/code7을 사용한다. [최신 초기 설정·배포 절차](SHARED_SHEETS.md)를 먼저 따른다. Cloudflare 인증과 Firestore는 필요하지 않으며 기존 데이터는 자동 이전/삭제하지 않는다. 아래 공개 상태 표는 과거 배포 기록이고 이번 코드의 실제 배포 완료를 뜻하지 않는다.

# 가족용 정식 배포

대상은 가족이 각자의 Google 계정으로 같은 원장을 사용하는 웹앱과 Android APK 직접 배포다. Google Play/App Store 출시나 불특정 다수 공개 서비스는 이 범위에 포함하지 않는다.

## 이번 릴리스 기준

- 웹: 화이트·차콜·블루 Bento UI, 가족 원장 CRUD, CSV, 설치/단축어 가이드, 공개 개인정보처리방침·약관.
- Android: 1.0.1 / versionCode 3, SMS 전용 수집 및 원본 메시지 기반 재수신 중복 방지.
- APK는 GitHub Releases, 다운로드 안내 페이지는 Firebase Spark Hosting에 게시한다.
- Google 인증 게시 상태는 콘솔에서 별도 확인한다. 테스트 모드라면 가족 이메일을 테스트 사용자로 등록해야 하며 Sheets 범위의 테스트 동의/토큰 만료 제한이 적용될 수 있다.
- 오프라인 기록·동기화는 지원하지 않는다. 실기기 검증은 이번 개발 작업에서 제외했다.

## 공개 상태 점검 (2026-10-21)

개발 환경에서 인증 없이 HTTPS로 조회한 결과다. 점검 후 배포가 진행되면 아래 기록보다 최신일 수 있다.

| 대상 | 확인 결과 | 다음 조치 |
|---|---|---|
| 웹 앱 코드·정책 문서 | 운영 OAuth ID로 재빌드한 main.dart.js·HTML·manifest·CSS와 공개 파일 해시 일치 | 이후 배포도 자동 비교 |
| `/privacy.html`, `/terms.html` | 최초 조회는 SPA fallback, 작업 중 재조회에서 실제 정책 문서·문의 이메일 확인 | 통합 배포 시 로컬 파일과 해시까지 비교 |
| APK 공개 메타데이터/다운로드 | 최초 조회 1.0.0, 최종 재조회에서 1.0.1 / code 3 및 실제 APK 크기·SHA-256 일치 | 기존 정식 앱에 1.0.1 업데이트 설치 |
| 최신 소스 CI | 3a1b18a 커밋의 web-and-sms/android 성공 | 추가 변경은 해당 PR 검사로 확인 |
| Google/가족 공유/GAS/실기기 | 사용자가 연결 성공 보고, 전체 운영 경로 독립 검증은 없음 | 아래 가족 사용 확인 |

## 한 번에 배포하기

본인 Cloud Shell에서 실행한다. Firebase와 GitHub 로그인, 기존 Android 서명키는 본인 계정에 보관한다. 키와 암호를 채팅에 보내지 않는다.

```sh
(
  set -e
  cd "$HOME/paylog"
  git pull --ff-only
  bash scripts/release-family.sh
)
```

이 명령은 GitHub 로그인 여부를 확인한 뒤 웹 빌드·Hosting 배포, Android 빌드·테스트·서명·GitHub 게시, 공개 웹·정책 문서·APK 검증을 수행한다. 마지막 성공 문구는 전체 단계가 통과할 때만 출력한다. 웹과 APK 게시가 하나의 원자적 작업은 아니므로 뒤 단계가 실패하면 앞 단계의 배포는 이미 반영됐을 수 있다.

- GitHub 인증 안내가 나오면 `gh auth login --hostname github.com --git-protocol https --web`을 실행한다.
- Firebase 인증 오류는 기존 Cloud Shell 로그인 계정과 프로젝트를 확인한다. 오래된 수동 토큰을 사용했다면 `unset FIREBASE_TOKEN` 후 CLI로 재인증한다.
- Android는 **기존 정식 서명키**를 재사용한다. 새 키로 교체하지 않는다. 같은 키의 1.0.1 APK를 기존 1.0.0 위에 설치하면 앱 설정을 유지할 수 있다. 업데이트 전에 대기 전송 상태를 확인한다.
- 이미 공개된 같은 버전의 APK는 다른 파일로 덮어쓰지 않는다. 코드 변경으로 새 APK가 필요하면 버전/코드를 올린다.

공개 상태만 다시 확인할 때는 빌드·배포 없이 다음을 실행한다.

```sh
python3 scripts/verify-release.py
# 지금 Cloud Shell에서 만든 웹 빌드까지 정확히 비교할 때
python3 scripts/verify-release.py --web-build apps/web/build/web
# Android 실패 후 검증을 유지하며 APK 업로드만 재시도할 때
python3 scripts/release-android.py --resume
```

공개 파일 검사는 실제 문서인지, 웹 파일이 로컬 빌드와 같은지, APK 버전·크기·SHA-256이 공개 메타데이터와 일치하는지 확인한다. APK 인증서가 본인 서명키와 일치하는지는 게시 전에 릴리스 스크립트가 검증한다. Google 로그인·시트 공유 권한·SMS 실수신까지 자동 확인하는 검사는 아니다.

## 가족 계정으로 사용 확인

1. 소유자가 자기 Google 계정으로 로그인하고 Sheets 접근에 동의한 뒤 원장을 생성 또는 연결한다. 상단이 **Sheets 원장**인지 확인한다. 샘플 모드의 데이터는 실제 원장에 저장되지 않는다.
2. Sheets 공유 메뉴에서 가족 이메일에 편집 권한을 부여한다. 가족은 자기 계정으로 로그인해 같은 원장을 연결하고 가족 참여를 진행한다. Members와 Google 공유 권한 모두 확인한다.
3. 금액이 작은 확인용 거래를 한 건 등록하고, 원장 새로고침/재로그인 후 같은 거래가 한 건인지 확인한다. 수정·삭제 및 상대 가족의 표시를 확인한다. 테스트 데이터 정리가 필요하면 앱의 삭제 표시와 시트 원본 행 삭제의 차이를 참고한다.
4. 문자 수집은 별도 GAS 수집 서버·카드/기기 등록이 완료된 이후 켠다. [SMS 운영 설정](sms-setup.md)을 따른다. 문자와 푸시 알림이 함께 와도 현재 앱은 SMS만 수집한다. 수신/검토함/취소 처리와 네트워크 재시도를 본인 기기에서 확인한다.
5. iPhone은 웹 수동 기록을 먼저 사용한다. 단축어 버튼은 앱을 여는 기능이며 자동화 구성을 대신하지 않는다. 고유 메시지 ID가 없는 전송은 검토함을 통해 처리한다.

## 백업·중지·복구

- 서명키: `cloudshell download "$HOME/.local/share/paylog-signing/paylog-release.p12"`로 암호화 키를 내려받고 암호를 따로 보관한다. 키 분실 시 같은 설치 앱의 업데이트가 어려워진다.
- 원장: 소유자가 Sheets 사본을 만들고 공유 권한을 제한한다. CSV는 현재 활성 거래의 내보내기이며 멤버/카드/기기/감사 이력을 포함하는 전체 원장 백업이 아니다.
- 잘못된 웹 배포: Firebase Hosting 콘솔에서 확인된 이전 릴리스로 되돌릴 수 있다. 웹 롤백은 이미 바뀐 시트 데이터를 복구하지 않는다.
- 문자 오수집: 우선 해당 Devices 항목을 비활성화해 추가 처리를 중지한다. 원장·검토함을 확인하고 기기 설정을 수정한다. Android 버전 다운그레이드는 데이터 보존을 보장할 수 없으므로 새 버전 수정 배포를 우선한다.
- Google 접근 중지: Google 계정 연결 관리에서 권한 철회, Sheets 공유 제거, 필요 시 GAS 배포 중지를 각각 수행한다.
