# Firestore 문자 수집 · Android 1.1.0

Spark 무료 플랜과 현재 Firebase 프로젝트를 그대로 사용한다. Cloud Functions·GAS·별도 서버·Google OAuth·푸시 알림은 필요하지 않다. 기존 Sheets 문자 수집은 기존 연결 파일로 유지되며 새 원장으로 자동 이전하지 않는다.

## 실제 지원 범위

| 기능 | 지원 |
|---|---|
| 웹 수동 수입·지출 등록, 상세 수정·삭제 | 기존 기능 유지. 문자에서 생성한 거래도 같은 화면에서 편집 가능 |
| Android 새 SMS 수집 | 새 APK 1.1.0과 버전 2 연결 파일 필요. 문자 수신 권한 허용 후 등록한 실제 발신자의 하나카드 승인·취소만 처리 |
| 원장 자동 반영 | 로그인한 가계부 웹이 열려 있을 때 등록한 카드의 해석 가능한 Android 승인만 반영. 웹을 닫은 동안에는 수집함에 저장하고 다음 접속 때 처리 |
| iPhone 전송 | 기기에서 Apple 메시지 자동화·단축어를 직접 구성해야 함. 웹앱은 SMS를 직접 읽지 못함 |
| iPhone 합산 | 신뢰할 수 있는 SMS 원본 고유 ID가 없으므로 자동 합산하지 않음. 웹 수집함의 ‘승인 기록 추가’로 확인 |
| 취소·미해석 문자 | 자동으로 금액을 빼거나 기존 거래를 지우지 않음. 원거래를 확인해 직접 수정·삭제하고 수집함에서 확인 완료 |
| 문자 앱/카드 앱 알림 | 읽지 않음. SMS와 알림이 같이 와도 알림 때문에 이중 수집하지 않음 |
| 다른 카드사·과거 SMS함 | 미지원. 하나카드라도 발신번호·식별자·형식이 다르면 자동 합산하지 않음 |

## 연결

1. 각자 아이디로 로그인하고 공동 가계부에 참여한다.
2. 설정 → **문자 자동 기록 · 기기 연결**에서 기기 이름, Android/iPhone, 실제 문자 발신번호, 문자에 표시된 카드 식별자(예: `하나1234`, `하나12**34`)를 입력한다. 여러 값은 쉼표로 구분한다. 발신번호를 임의로 추측하지 않는다.
3. **휴대폰 연결 파일 만들기 → 다운로드**. 기기마다 새 파일을 만든다. 원문 비밀번호는 생성 당시 파일에만 포함되며 Firestore에 보관하지 않는다. 다운로드 실패 후 다시 만들었으면 사용하지 않는 이전 기기를 차단한다.
4. Android는 같은 소유자 서명키로 배포된 **1.1.0** APK에 업데이트하고 **연결 파일 선택 → 연결 → 문자 권한 허용하고 시작**한다. 기존 대기 문자가 있으면 먼저 기존 연결로 전송하거나 확인 후 삭제해야 교체할 수 있다. 파일을 가져온 뒤 다운로드 사본을 삭제한다. 프로덕션 APK는 `paylog-c5c2d`의 공개 설정만 허용한다.
5. 등록한 카드사의 실제 승인 문자를 받고 앱의 ‘Firestore 수집함 전송 확인’ 상태와 웹 거래를 확인한다. 실기기 검증 전에는 테스트 금액을 기준으로 확인한다. 원장을 닫고 받은 문자는 다음 접속 시 처리된다.
6. 분실·연결 교체 시 웹 기기 목록에서 **차단**한다. 기존 로그인 토큰이 남아 있어도 규칙이 새 전송을 차단한다. 이미 처리 중인 요청은 먼저 완료됐을 수 있다. 이미 수집된 본문은 수집함에서 확인 완료로 지울 수 있다.

## iPhone 단축어

[구성 레시피](../ios/firestore-shortcut-template.json)는 서명된 `.shortcut`이 아니므로 단축어 앱에서 직접 구성해야 한다. 웹에서 iPhone을 골라 만든 설정 JSON을 사용한다. 레시피는 기기 계정 로그인 → ID 토큰으로 Firestore REST `commit` → 수집함 전송 순서다. `createdAt`은 클라이언트 시각을 직접 넣지 않고 `updateTransforms`의 `REQUEST_TIME`을 사용한다. JSON 본문은 사전 동작으로 만들어 문자 따옴표·줄바꿈이 깨지지 않게 한다. API 키는 공개 설정이고, 기기 이메일·비밀번호는 공유하면 안 되는 전송 자격 증명이다. 사람의 아이디·비밀번호를 단축어에 넣지 않는다.

메시지 자동화는 발신번호로 좁히고 iOS가 지원하면 ‘즉시 실행’을 사용한다. OTP·인증번호·비밀번호 및 카드 승인/취소가 아닌 본문은 전송하지 않는다. 한 실행의 재전송은 같은 `messageId`·`receivedAt`을 유지한다. 새로운 UUID로 재실행한 문자는 별도 후보가 되므로 웹에서 기존 기록을 먼저 확인한다. 자동화 실행/본문 전달은 iOS 버전에 따라 실기기 확인이 필요하다.

## 보안·중복·보관

- 웹은 원래 로그인과 분리된 이메일/비밀번호 REST API로 임의 256비트 기기 비밀번호를 생성한다. 내부 주소는 `device_<난수>@devices.paylog.invalid`다. 기기 계정은 인간 계정의 프로필·가계부·거래를 읽거나 수정하지 못하며, 등록된 가계부의 자기 문자만 새로 생성하고 자기 전송 결과만 확인한다. 기기 비밀키는 설정 파일과 Android Keystore 암호화 저장소에만 보관한다. 사람의 로그인 토큰을 내보내지 않는다.
- Android는 원본 SMS 파트 시각·발신자·본문의 안정적인 ID를 재시도에도 유지한다. 원문은 휴대폰의 암호화 대기열에 보관하며 최대 100건/7일 제한을 유지한다. 카드 알림은 별도 수집하지 않는다.
- Firestore 수집함은 기기별 원본 ID로 create-only 저장한다. Android는 생성 충돌 시 기존 `bodyHash`·발신자·기기/메시지 ID를 검증한 후에만 큐를 삭제한다. 오류/권한 거절을 성공으로 표시하지 않는다.
- 웹은 `smsReceipts/{원본ID}`와 `transactions/sms_{원본ID}`를 같은 트랜잭션으로 생성하고 수집함을 처리 완료한다. 여러 브라우저의 동시 처리나 다른 기기의 **동일 원본 ID·본문 해시·발신자**는 거래를 중복 생성하지 않는다. 거래를 수정·삭제 표시해도 영수증은 남아 재수신이 원장을 되살리지 않는다. 확인 완료로 제외한 문자도 같은 원본 ID의 제외 기록을 남겨 다른 기기에서 다시 합산하지 않는다.
- 통신사가 원본 시각/본문을 바꾸거나 iPhone 자동화를 새 UUID로 다시 실행하면 다른 메시지일 수 있다. 금액·가게·분 단위 시각만으로 실제 별도 결제를 임의로 합치지 않는다. 동일 카드 문자를 여러 기기에 연결할 때 이 한계를 확인한다.
- 미처리 카드 문자 본문은 Firestore 수집함에 저장되어 같은 가계부 멤버가 볼 수 있다. 수집 화면에서 이를 안내한다. 자동 반영/확인 완료 시 본문은 빈 문자열로 덮어쓰고 해시·처리 결과만 보관한다. 거래와 별도로 내려받은 사본·휴대폰 대기열은 사용자가 관리한다. 다른 서비스의 백업 보관 정책은 별개다.
- 같은 기기 계정을 재사용하지 않는다. 전송 전용 Auth 계정 삭제·Firestore 자료의 완전 삭제는 운영자 절차다. 발급 중 실패한 미연결 계정은 Firestore 권한이 없으며 Auth 콘솔에서 정리할 수 있다.
- 수집함은 미처리 50건씩 표시하고 처리 후 다음 건을 읽는다. 기기 목록은 50개 표시하며 멤버 인원수 제한과는 별개다. 보안 규칙과 활성 가계부 범위로 조회한다.

## 배포와 기기 확인

웹/규칙: `bash scripts/deploy-cloud-shell.sh`. Android: **소유자 Cloud Shell에서** `python3 scripts/release-android.py`. APK는 기존 서명키로 1.1.0을 게시해야 실제 폰에서 새 기능을 쓸 수 있다. Spark를 Blaze로 바꾸지 않는다.

실제 SMS 수신·삼성 배터리 제한·오프라인 후 재전송·Android Keystore·iPhone 메시지 자동화는 코드/에뮬레이터 검증과 별개다. 기기에서 수동 등록/수정/삭제, 자동 승인, 재전송, 취소 검토, 차단 후 전송 거절을 확인한다. Play Protect 설치 정책은 이 전환으로 해결된다고 보장하지 않는다.
