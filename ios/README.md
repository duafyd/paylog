# iPhone 16 Pro 단축어 설정

이 디렉터리는 동작 구성도와 수동 설정 절차다. `sms-shortcut-template.json`은 Apple 서명이 있는 `.shortcut` 파일이 아니며 바로 가져올 수 없다. 이 Linux 환경에서는 Apple 단축어 서명 도구를 사용할 수 없어 가져오기 파일을 생성·서명하지 않았다. 실제 메시지 입력 변수, 무확인 자동 실행, 홈 화면 PWA 로그인은 실기기 검증 대상이다.

1. `docs/sms-setup.md`에 따라 소유자가 iOS 기기 UUID·토큰 해시를 Devices에 등록한다. 원본 토큰은 기기에만 입력한다.
2. 단축어 앱에서 새 단축어 `paylog 문자 전송`을 만든다. 입력으로 텍스트를 받도록 설정한다. 공유 시트 사용도 켜면 문자 복사/공유를 통한 수동 대체 경로가 된다.
3. 사전(Dictionary)에 `action=sms.ingest`, `deviceId=본인 UUID`, `ingestToken=기기 토큰`, `body=단축어 입력 텍스트`, `receivedAt=현재 날짜를 ISO 8601 및 시간대 포함 형식으로 포맷`을 설정한다. `sender`는 자동화가 실제 제공하는 발신자 값을 쓴다. 제공하지 않으면 발신자 조건으로 한정한 자동화에 실제 등록 번호를 고정 입력하며 이 값은 수집된 메타데이터가 아니라 설정값임을 구분한다. 여러 발신자는 자동화를 분리한다.
4. 실제 고유 메시지 ID를 제공할 때만 `messageId`를 추가한다. 임의의 새 UUID를 매 재시도마다 만들지 않는다. ID가 없는 요청은 검토함으로 이동하며 자동 결제 합계에 포함되지 않는다. 수동 재전송은 최초 사전의 receivedAt을 그대로 유지한다. 현재 날짜를 새로 만들면 별도 검토 항목이 될 수 있다.
5. `URL 콘텐츠 가져오기`: 본인 GAS `/exec` HTTPS URL, 메서드 POST, 요청 본문 JSON에 위 사전을 넣는다. JSON을 URL 쿼리로 보내지 않는다. 응답에서 `ok`와 `code`를 확인한다. `CREATED/DUPLICATE/IGNORED_CARD/REVIEW_REQUIRED`만 처리 완료로 안내한다. 인증/형식/재시도 오류는 원문을 알림에 표시하지 말고 전송 실패 안내만 표시한다.
6. 자동화 → 메시지 수신에서 실제 카드사 발신자로 좁힌다. 해당 iOS 버전에서 제공되는 메시지 입력을 위 단축어에 전달한다. ‘즉시 실행’ 선택 및 확인 요구 여부는 기기에서 확인한다. 본문 변수가 비어 있거나 실행 확인이 필수이면 자동 수집 완료로 간주하지 않는다.
7. 수동 대체 경로: 문자 본문을 복사 → 공유 시트/단축어 실행 → 성공 여부 확인 → 웹 검토함에서 후보 확인 후 수동 등록. PWA는 SMS를 직접 읽을 수 없다.

단축어에 평문 토큰이 포함되므로 공유/내보내기 시 반드시 제거한다. 노출되면 Devices를 비활성화하고 새 토큰을 발급한다. 단축어/iCloud 공유 상태를 점검한다. 서버는 SMS 원문을 보관하지 않는다. iOS 단축어 자체 기록·클립보드·화면 캡처에 대한 노출은 사용자가 관리해야 한다.
